KV Cache：今天真正弄懂

先记住

先记住：一句话定义 + 一句记忆口诀

通俗讲解

一句话定义：自回归生成（逐字输出）时，把之前算过的 Key 和 Value 向量存入显存，新词只算自己的 Query，直接复用历史 KV，从而避免重复计算。

生活类比： 你在开一场长会做会议记录。 - 没有 KV Cache：每次新来一句话，你必须把前 100 句话从头到尾重新听一遍、重新解析一遍语法，才能写下新一句话。 - 有 KV Cache：前 100 句话的笔记已经整齐放在桌上。新来一句话，你只需理解这一句，然后翻看桌上的旧笔记做对照，直接写下新记录。

核心公式与符号拆解： 标准自注意力公式为： $$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{Q K^T}{\sqrt{d_k}}\right) V$$

在自回归生成的第 $t$ 步： 1. **$Q_t$（当前查询）**：只有当前生成的这 1 个 token 的向量，形状为 $[1, d_k]$。 2. **$K_{\le t}$（累积键）**：历史缓存的 $K_{< t}$ 拼上当前的 $K_t$，形状为 $[t, d_k]$。 3. **$V_{\le t}$（累积值）**：历史缓存的 $V_{< t}$ 拼上当前的 $V_t$，形状为 $[t, d_v]$。 4. **$d_k$**：隐藏层向量维度，除以 $\sqrt{d_k}$ 是为了防止点积过大导致梯度消失或 Softmax 极化。

它解决什么问题？ 自回归模型（如 Whisper 解码器、LLaMA）必须一个词一个词往后蹦。在生成第 1000 个词时，前 999 个词的语义投影（$K$ 和 $V$）在数学上完全没变。 - 没有它：生成第 $N$ 个词需要重新计算前 $N-1$ 个词的所有矩阵乘法，整体推理总计算量是 $O(N^3)$ 级别，越往后生成越卡。 - 有了它：每一步只算当前 1 个词的投影，再做一次轻量拼接，单步计算量降为 $O(N)$，整体计算量降为 $O(N^2)$。

在音视频理解与说话人日志中的实际位置： 1. Whisper / 语音识别 Decoder：在转写长音频时，Decoder 内部自注意力层会用 KV Cache 记住已经转写出的文本历史，避免每输出一个字就重扫一遍前面所有字。 2. 端到端说话人日志（Diarization）：模型自回归输出“说话人标签+时间戳”时，Decoder 利用 KV Cache 记住“上一秒是谁在说话”，保证说话人判别的时序连贯性。 3. 视频多模态问答：视频特征通常作为长 Prompt 一次性计算出 KV 并存入缓存，后续文本交互直接复用视频 KV，不用反复重跑视频编码。

*学习建议*：想要看官方工程实现，可参考 Hugging Face 缓存说明，它非常适合用来学习 `DynamicCache` 的具体张量结构与生成循环 API。

先想再展开答案
为什么新生成的 token 只需要 1 个 Q 向量？
因为当前只需要计算“最新生成的这 1 个词”与“历史所有词”之间的注意力权重，不需要重复计算历史词之间的关系。
KV Cache 是用什么代价换取了什么收益？
用显存空间换取了推理计算时间（减少了重复的前向投影矩阵运算）。
在跨注意力机制（Cross-Attention）中，音频特征的 KV Cache 需要每步更新吗？
不需要。音频特征作为输入是固定不变的，只需要在第 1 步计算一次 KV 并永久缓存，后续自回归步直接复用即可。
发展脉络 · 现状 · 未来

发展流程： 1. 过去（无缓存）：早期 Transformer 只做整句翻译，一次前向直接出结果。转向文本生成后，简单粗暴地把 `[历史+新词]` 整体反复送入模型，计算大量冗余。 2. 现在（标配标准）：几乎所有自回归模型（LLM、语音转写 Decoder）默认开启 KV Cache。业界演进出了 MQA（Multi-Query Attention）和 GQA（Grouped-Query Attention），核心目的就是为了大幅减少 KV Cache 的显存占用。 3. 相近概念辨析： - KV Cache vs 激活值缓存（Activation Cache）：激活值缓存用于训练阶段的反向传播求导；KV Cache 专用于推理阶段复用中间注意力的 $K$ 和 $V$。 - KV Cache vs Prompt Caching：Prompt Caching 指跨请求复用静态前缀（如固定的系统提示词）；KV Cache 是单次推理内部逐步累加动态上下文。

当前局限与未来趋势： - [事实局限] 空间换时间，显存开销极大。并发用户多或上下文超长时，显存会被 KV Cache 挤爆（显存墙）。 - [未来推测] 在长音频/实时视频流式日志场景下，基于滑动窗口（如 StreamingLLM）或时序自适应丢弃的动态 KV Cache，可能会成为边缘端低显存实时部署的标准方案。

动手练习 第二则

KV Cache：动手实现

练习目标

目标：用 PyTorch 手写一个最小自注意力模块，实现“无 Cache 完整计算”与“带 KV Cache 增量计算”，并验证两者的数值输出完全一致。 输入：Batch 大小为 1，隐藏维度 16，历史序列长度 3，新输入 1 个 token。 输出：单步预测的 Attention 输出向量，以及更新后的 Cache。 验收标准：带 Cache 与不带 Cache 的计算结果误差小于 $10^{-5}$。

参考实现

思路： 1. 实现一个单头注意力：包含 $W_q, W_k, W_v$ 线性映射。 2. 无 Cache 模式：输入整个序列 $[B, T, D]$，计算完整注意力，取最后一步的输出。 3. 带 Cache 模式：输入当前单 token $[B, 1, D]$ 和历史 `past_k`, `past_v`。只对单 token 算 $Q, K, V$，把 $K, V$ 拼到历史 Cache 中，再用单点 $Q$ 与完整 $K, V$ 做注意力。

import torch
import torch.nn as nn
import torch.nn.functional as F

class MinimalAttentionWithKVCache(nn.Module):
    def __init__(self, dim):
        super().__init__()
        self.dim = dim
        self.w_q = nn.Linear(dim, dim, bias=False)
        self.w_k = nn.Linear(dim, dim, bias=False)
        self.w_v = nn.Linear(dim, dim, bias=False)

    def forward_no_cache(self, x):
        # x: [Batch, Seq_Len, Dim]
        B, T, D = x.shape
        q = self.w_q(x)  # [B, T, D]
        k = self.w_k(x)  # [B, T, D]
        v = self.w_v(x)  # [B, T, D]

        # 计算因果注意力 (自回归只能看过去)
        scores = torch.matmul(q, k.transpose(-2, -1)) / (self.dim ** 0.5)
        mask = torch.tril(torch.ones(T, T, device=x.device))
        scores = scores.masked_fill(mask == 0, float('-inf'))
        attn = F.softmax(scores, dim=-1)
        out = torch.matmul(attn, v)  # [B, T, D]
        return out[:, -1:, :]        # 取最后一个 token 的输出

    def forward_with_cache(self, x_new, past_k=None, past_v=None):
        # x_new: [Batch, 1, Dim] 仅传入当前生成的 1 个 token
        q_new = self.w_q(x_new)  # [B, 1, D]
        k_new = self.w_k(x_new)  # [B, 1, D]
        v_new = self.w_v(x_new)  # [B, 1, D]

        if past_k is not None and past_v is not None:
            # 拼接历史 KV
            k_full = torch.cat([past_k, k_new], dim=1)  # [B, T_past + 1, D]
            v_full = torch.cat([past_v, v_new], dim=1)  # [B, T_past + 1, D]
        else:
            k_full, v_full = k_new, v_new

        # 当前 1 个 token 对过去所有 token 算注意力，无需 Mask
        scores = torch.matmul(q_new, k_full.transpose(-2, -1)) / (self.dim ** 0.5)  # [B, 1, T_full]
        attn = F.softmax(scores, dim=-1)
        out = torch.matmul(attn, v_full)  # [B, 1, D]

        return out, k_full, v_full

# ================= 验证正确性 =================
torch.manual_seed(42)
dim = 16
model = MinimalAttentionWithKVCache(dim)

# 模拟 3 个历史 token，加 1 个新 token
x_past = torch.randn(1, 3, dim)
x_new = torch.randn(1, 1, dim)
x_full = torch.cat([x_past, x_new], dim=1)  # [1, 4, 16]

# 1. 无 Cache 计算（全序列输入）
out_no_cache = model.forward_no_cache(x_full)

# 2. 带 Cache 计算（分步传入）
# 先让模型处理前 3 个 token，拿到历史 KV Cache
_, past_k, past_v = model.forward_with_cache(x_past)
# 新 token 到来，只传 x_new 和历史 Cache
out_with_cache, _, _ = model.forward_with_cache(x_new, past_k, past_v)

# 3. 对比误差
diff = torch.max(torch.abs(out_no_cache - out_with_cache)).item()
print(f"输出形状: {out_with_cache.shape}")
print(f"两种方式的最大绝对误差: {diff:.8f}")
assert diff < 1e-5, "验证失败：Cache 计算结果与全量计算不一致！"
print("✅ 验证成功：KV Cache 逻辑完全正确！")
代码拆解与真实用法

代码逐段解析： 1. `forward_no_cache`：模拟传统做法。每次将整个句子 `x`（长度为 $T$）传入，做 $O(T^2)$ 的全量注意力矩阵乘法，再切片 `out[:, -1:, :]` 取出最后一个位置的输出。 2. `forward_with_cache`： - 投影只发生在输入张量 `x_new` 上（长度恒为 1），计算耗时恒定。 - `torch.cat([past_k, k_new], dim=1)`：在时间序列维度（`dim=1`）完成拼接。 - `scores` 的形状为 $[B, 1, T_{full}]$，由于只有 1 行，它自然能“看见”过去所有的 Key，完全不需要因果 Mask（三角掩码），省去了掩码计算。 3. 常见错误： - 拼接维度搞错：如果写成 `dim=-1` 会拼在特征维度上，导致张量形状错乱。 - 在有 Cache 的情况下仍去计算 $Q_{past}$：Query 只需要当前步的，千万不要去给历史 token 重复算 Query。 4. 真实模型对应：该逻辑完全对应 Hugging Face 中 `WhisperDecoderLayer` 或 `LlamaAttention` 中 `past_key_value` 的核心拼接操作。
